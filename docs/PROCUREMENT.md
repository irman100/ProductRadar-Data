# Product Radar — закупочная витрина

Главная страница: `web/procurement/index.html`. В браузере она загружает `data/procurement/evidence.json` напрямую из GitHub при открытии и по кнопке обновления, применяя проверку свежести на текущую дату. Исследования не выполняются автоматически самим браузером: обновление загружает уже опубликованные факты. Старый unified.json и история исследований сохраняются; прежний каталог доступен по ссылке «Архив каталога». Не включать непроверенные позиции в закупочную подборку.

## Публикация данных после каждого исследования

1. Сохранить датированные сырые наблюдения в data/research, обновить карточку в unified.json при наличии достаточных доказательств, затем обновить evidence.json, сохраняя историю в датированном отчёте. Не удалять старые позиции из архива.
2. Найти точно совпадающую заводскую модель, вариант, цвет, комплектацию, технические характеристики и региональную версию. Приоритет прямых предложений Alibaba и 1688, далее другие китайские площадки/поставщики. Ссылки на поисковые категории и неподтверждённые аналоги не считаются предложениями поставщика. Использовать только публичные сведения, без персональных данных, закрытых котировок и секретов.
3. Подтвердить счётчик накопленных покупок конкретной карточки (не отзывы и не продажи за период), минимум 100 — редакционный порог, не доказательство месячного оборота. Минимум две независимые российские площадки: одинаковый вариант, наличие, цены без специальных условий, дата не старше 7 дней. Среднее считается по минимальной подходящей цене каждой площадки, расчёт прибыли — по минимальной из них. Условные цены Пэй, цены с купоном, трансграничные и устаревшие предложения хранить отдельно.
4. Китайская цена должна относиться к конкретному количеству, иметь размер MOQ, источник, валюту, дату курса, дату котировки и срок действия. Уточнить оригинальность, наличие партии, документы и право на бренд. Для партии считать стоимость ввоза, включая доставку, страхование, пошлины, невозмещаемые налоги и распределённые затраты на оформление/сертификацию. Расходы продажи: комиссии, доставка до клиента, реклама, возвраты и налоги — без двойного учёта. Ноль допустим только при подтверждённом отсутствии расхода.
5. Для допуска нужны реальные фото точного варианта на обоих рынках. Резервные изображения можно хранить отдельно с fallback_image_url и fallback_image_type; синтетика маркируется как иллюстрация и не служит доказательством совпадения. Не сохранять чужие изображения без права использования.
6. Проверить расчёт: чистая прибыль на единицу = конкурентная цена × (1 − sales_pct/100) − цена Китая − import_per_unit_rub − sales_fixed_per_unit_rub − taxes_per_unit_rub − other_per_unit_rub. Чистая расчётная маржа = прибыль / конкурентная цена × 100. Стоимость партии с ввозом = (цена Китая + import_per_unit_rub) × quote_quantity. Порог маржи 15%, бюджет 5–300 тыс. ₽. Это критерий отбора, не гарантия прибыли. Кандидат со свежими ценами, фото РФ, спросом и ценовым запасом может показываться отдельно, но не как готовая закупка. Сценарий 20% расходов продажи условный; не подменяет реальные затраты.
7. Проверить опубликованный JSON повторным чтением и `node scripts/validate_procurement.js`. Витрина использует тот же gate, встроенный в HTML. При изменении логики синхронно обновить gate и HTML и повторно выполнить установку новой версии. Для изменения товаров, цен, выводов и ссылок достаточно обновить evidence.json; переустановка не нужна.

## Схема records

- id, name, model, category, checked_at (YYYY-MM-DD), variant_key (общий идентификатор точного варианта), review_status, decision.
- ru: url, image_url, image_status=exact_photo_verified, availability_verified, demand={value,type:cumulative_purchases,url,verified,observed_at}, offers=[{platform,url,price_rub,currency:RUB,price_type:public_unconditional_retail_offer,in_stock:true,match_confidence:exact_sku,variant_key,observed_at}]. Для предварительного сравнения дополнительно benchmark_rub и available_on_page, явно отмечать условия цены.
- china: url, seller, variant_key, match_verified, match_source_url, unit_rub, price_cny или price_usd, moq, quote_quantity, quote_verified, quote_date, quote_valid_until, quote_source_url, supplier_verified, image_url, image_status, match_note. Для предварительного предложения public_price_checked_at.
- economics: verified, checked_at, source_urls, import_per_unit_rub, sales_fixed_per_unit_rub, sales_pct, taxes_per_unit_rub, other_per_unit_rub. Неизвестные значения — null. Не ставить verified=true, если источники не подтверждают полный расчёт.
- scenarios и scenario_labels — дополнительные стресс-сценарии, не подтверждённая маржа.
- Схема верхнего уровня: dataset=procurement_evidence, schema_version, checked_at, policy, fx, archive_catalog_count, records. Политика в браузере закреплена: 100 покупок, 7 дней, 15% маржа, 5000–300000 ₽. Для её изменения требуется явное изменение кода. Все даты сверяются с актуальной датой, не с датой публикации. Сохранить отчёт при каждом обновлении.

## Установка на Orange Pi

`python3 scripts/install_procurement.py --check` — проверка скачанного закреплённого HTML, без изменения сайта. `python3 scripts/install_procurement.py` — одноразовая установка, резервная копия index.html, прежняя страница catalog-archive.html, проверка SHA Git blob, локальная проверка чтения, без перезапуска контейнера. Если каталог уже существует и не был установлен новый индекс, скрипт отказывается перезаписывать его. При ошибке записи восстанавливается резервная копия. Путь по умолчанию: /home/dockeruser/product-radar-public/index.html. Если браузер сохраняет старую страницу через service worker, обновить с Ctrl+F5; при необходимости очистить данные сайта/отменить регистрацию старого service worker. Работа на реальном Orange Pi и мобильном браузере требует проверки после установки.
