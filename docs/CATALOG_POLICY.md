# Product Radar — публикация каталога

## Источник данных и дисковое хранение

- Основной каталог: `data/research/products.json` в этом публичном репозитории GitHub.
- Данные категорий: `data/research/categories.json`.
- Публичный сайт: `docs/index.html`, с отдельной копией фронтенда в Nginx на Orange Pi.
- Браузер читает JSON напрямую с GitHub Raw через HTTPS, не из SQLite на Orange Pi.
- Фотографии на данный момент **не копируются на Orange Pi**: хранятся URL фотографий на сайтах продавцов и ссылки на страницы-источники.
- Старые локальные базы Product Radar на Windows и база HuDu не являются источником публичного каталога.

## Правило для новых товаров

Каждая опубликованная карточка обязана содержать `id`, `name`, `category`, `reasoning`, `risk`, `chinese_query`, `image_url`, `image_source_url`, `image_source_title`, `image_checked_at`, `image_note`, `image_kind=merchant_example`.

- Нет подтверждённой ссылки на реальную фотографию и её товарную страницу? **Не добавлять в публичные товары.**
- Не заменять отсутствующие фотографии сгенерированными иллюстрациями.
- Гипотеза продаж не равна доказанному спросу. Фотография похожего товара не является подтверждением SKU или фабрики.
- При каждом изменении `products.json` запускается `scripts/validate_products.py` через GitHub Actions. Публикующий интерфейс также фильтрует неполные записи.
- Изображения размещены на сторонних доменах: ссылки могут устареть, а встраивание может быть запрещено. Интерфейс скрывает карточку, фотография которой не загрузилась.
- В случае перехода к локальному хранению фото проверить условия использования/лицензии и использовать постоянный разрешённый хостинг. Не копировать фотографии продавцов без соответствующих прав.

## Проверка

```bash
python3 scripts/validate_products.py data/research/products.json
```

### Размещение

Домашний сервер Orange Pi содержит лишь файлы фронтенда в `/home/dockeruser/product-radar-public`; Docker-контейнер `product-radar-web` раздаёт их по `10.77.0.2:8766`, а VDSina Caddy проксирует `radar.hugedune.ru` по WireGuard. Сама товарная база остаётся в GitHub.


## Дополнение для единой витрины (2026-11-18)

Сайт теперь отображает `data/catalog/unified.json`, объединяющий уже опубликованные предметные предложения без повторения товарных URL. Это отдельная от старой `data/research/products.json` витрина; старые строгие требования к исследовательскому файлу сохраняются.

- Для единой витрины обязательно: точная карточка продавца (`url`), название, группа, источник исследования. Прямая ссылка на изображение желательна, но не является условием существования карточки.
- Фотографии берутся из `image_url` товара и дополнительного `data/catalog/images.json`. Автоматический `scripts/refresh_merchant_images.py` ищет только публичные метаданные изображения на странице продавца, **не скачивает и не хранит файлы фото**; источники и дата отмечаются в индексе.
- Одного URL изображения недостаточно, чтобы гарантировать разрешённое встраивание или что изображение загрузится из браузера. Учитывайте лицензии и правила продавцов. Если фотохостинг блокирует встраивание, показывайте аккуратную заглушку и прямую ссылку на оригинальную карточку, не скрывайте товар.
- Категорически не заменять фото точного SKU изображением другого цвета, модели или похожего аналога без явного пояснения.
- Существование карточки, внешняя фотография, отзывы или поисковые выдачи не означают подтверждённые продажи, наличие складских остатков, проверенного поставщика из Китая или прибыльность.
- Источник: `data/catalog/images.json`, проверка: `.github/workflows/merchant-images.yml`. Результат выполнения нужно подтверждать отдельно; наличие workflow не доказывает, что фото уже найдены.
